# Book-cover asset pipeline

`node scripts/fetch-covers.mjs` turns a plain list of books into ready-to-use
cover art for the 3D shelf: real cover photography where it can be found,
and a deliberately-designed typographic cover where it can't.

## Usage

```
npm run covers                       # process everything not already cached
node scripts/fetch-covers.mjs --force            # re-download/regenerate everything
node scripts/fetch-covers.mjs --only=some-book-id # process a single entry
```

If `src/data/covers.json` doesn't exist yet, the script writes an example to
`scripts/covers.example.json` (see schema below) and exits `0` — it never
crashes just because the data hasn't been authored.

## The other scripts

| script | what it does |
| ------ | ------------ |
| `build-covers-input.mjs` | Generates `src/data/covers.json` by joining the bibliography (`books.json`) with the publisher cover URLs (`cover-sources.json`). Run automatically by `npm run covers`. **`covers.json` is a build artefact — edit the two inputs, not it.** |
| `fetch-covers.mjs` | This script. Downloads, resizes and colour-samples the covers. |
| `merge-synopses.mjs` | Folds `{ id: { ca, es, en, de, fr } }` files into the `synopsis` field of `books.json`, leaving every other field alone. Rerunnable; later files win. |
| `build-og.mjs` | Composites the five most recent covers into `public/og-default.png`, the social preview card. Run after the covers exist. |

`npm run assets` chains covers + OG card, which is the usual thing to run after
adding a book.

## Input: `src/data/covers.json`

An array of book entries, generated by `build-covers-input.mjs`:

```json
[
  {
    "id": "slug-del-libro",
    "title": "Título de la traducción",
    "author": "Autor original",
    "publisher": "Editorial",
    "isbn": "9788412345678",
    "sourceUrl": "https://…/cover.jpg"
  }
]
```

| field        | required | notes                                                              |
| ------------ | -------- | ------------------------------------------------------------------ |
| `id`         | yes      | slug; used as the output filename and the shelf's stable key       |
| `title`      | no       | shown on the generated fallback cover if one is needed             |
| `author`     | no       | shown (small caps) on the generated fallback cover                 |
| `publisher`  | no       | shown at the foot of the generated fallback cover                  |
| `isbn`       | no       | ISBN-13 (or 10), used to look up cover art                         |
| `sourceUrl`  | no       | explicit image URL; tried before any ISBN lookup                   |

## What it does, per book

1. If `public/covers/<id>.webp` already exists and `--force` wasn't passed,
   skip straight to re-reading it for metadata (logged as `cached`).
2. Otherwise, resolve a source image, trying in order and stopping at the
   first success:
   - the explicit `sourceUrl`, if present;
   - Open Library: `https://covers.openlibrary.org/b/isbn/<isbn>-L.jpg`.
     Open Library returns a tiny placeholder image (commonly ~43 bytes,
     1×1px) when it has no cover for that ISBN, so any response under
     ~3&nbsp;KB or narrower than 200px is treated as "no cover" rather than
     accepted;
   - Google Books:
     `https://www.googleapis.com/books/v1/volumes?q=isbn:<isbn>`, reading
     `items[0].volumeInfo.imageLinks` and preferring `extraLarge` >
     `large` > `medium` > `thumbnail`. The URL is cleaned up
     (`&edge=curl` stripped, `zoom=1` bumped to `zoom=3`) to get a larger,
     non-overlaid raster.
3. If an image was found: resize with `sharp` to 800px wide (aspect ratio
   preserved) as `public/covers/<id>.webp` at quality 82, plus a 320px-wide
   `public/covers/<id>-thumb.webp`.
4. If no image was found anywhere: generate a typographic fallback cover
   instead of leaving a hole — an 800×1200 canvas in a deterministic muted
   colour (hashed from `id` into a curated ~10-tone warm editorial palette),
   a thin inset rule border, the title word-wrapped in a serif stack
   (auto-shrinking the font size for long titles), the author above it in
   letterspaced small caps, and the publisher at the foot. All text is
   XML-escaped, since real titles contain `&`, quotes and accents.
5. Either way, the final raster is analysed with `sharp`'s `.stats()` to get
   a dominant colour, which is darkened/desaturated slightly so it reads as
   a book spine rather than a washed-out photo average. A readable
   foreground (`#faf7f2` or `#1a1613`) is picked via WCAG contrast against
   that spine colour.
6. All of the above is collected into `src/data/cover-meta.json`
   (`{ id, spineColor, textColor, width, height, source }`, pretty-printed,
   sorted by `id`) so the shelf can theme itself without re-touching images,
   and the build is reproducible. Entries untouched by an `--only` run keep
   their previous metadata rather than being dropped.
7. A summary table is printed at the end (per book, which source won).
   The process only exits non-zero on unexpected internal errors — a
   missing cover is never treated as a failure, since the fallback handles
   it.

`source` in the metadata is one of `"url"`, `"openlibrary"`, `"googlebooks"`,
or `"generated"`.

## Network / proxy notes

Outbound requests go through whatever `HTTPS_PROXY`/`HTTP_PROXY` is set in
the environment. Node's built-in global `fetch` does not honour those
variables on its own, so `scripts/lib/http.mjs` picks a strategy lazily:

- if a proxy env var is set **and** `undici` can be dynamically imported,
  it's used with an `undici.ProxyAgent` pointed at that proxy;
- otherwise it shells out to `curl` (via `execFile`, not a shell string) for
  the actual request, since `curl` already respects the standard proxy env
  vars and CA trust configuration wherever this script runs.

Either path returns `{ status, buffer }` (or `{ status, text }`), and a
non-2xx status is treated the same as a thrown error by callers: "no image
here, try the next source."

## Output

- `public/covers/<id>.webp` — 800px-wide cover, quality 82.
- `public/covers/<id>-thumb.webp` — 320px-wide thumbnail, quality 82.
- `src/data/cover-meta.json` — per-book metadata (this is the one file this
  script writes under `src/data/`).

## Flags

- `--force` — ignore the cache and re-download/regenerate every cover.
- `--only=<id>` — process a single book by id.
